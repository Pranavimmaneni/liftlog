## How the two looks coexist (read before editing)

- The look is a setting: `useDesign()` from `@/app/design` returns `'classic' | 'sun'`. **Classic must render exactly as before** and every existing test must keep passing unedited. Branch on the look inside the screen.
- Two patterns, pick per screen:
  1. Small differences: `const sun = useDesign() === 'sun'` and conditional class names / fragments.
  2. A different layout: keep the classic component as it is, move shared state into a hook in the same folder, and add `<Name>Sun.tsx`. See `src/screens/S05-home/{data.ts,index.tsx,HomeSun.tsx}`, `S06-workout/{state.tsx,WorkoutSun.tsx}` and `S07-logger/{useLogger.ts,LoggerSun.tsx}` for worked examples. Do not copy business logic into the Sun file.
- What already happens for free in the new look (from `src/styles/sun.css`, which restyles the shared classes): tokens for all four themes, Hanken Grotesk body type, `.ll-card` = glass, `.ll-btn` variants, `.ll-chip`, `.ll-row`, `.ll-input`, `.ll-icon-btn`, `.ll-link`, segmented control, switch, sheet, tab bars, stepper, and `<ScreenHeader>` renders the glass sub-screen bar. The sun backdrop is now behind every screen except the scanners.
- What each screen still needs:
  - **Nothing but the page title may sit straight on the page.** Text over the sun's disc and rings is unreadable. Put content on glass: `className="sun-glass rounded-[18px] p-[18px]"` for hero cards, `rounded-[14px]` for lists (or `.ll-card`).
  - Display type: `.t-display` keeps the old condensed face in the new look on purpose (D128). On a rebuilt screen use `.sun-title` (30 px screen title) and `.sun-display` with the mockup's size (hero numbers 38–54 px, small display 19–27 px). The face is very wide: check 360 px, allow wrapping (`break-words`), never `whitespace-nowrap` a long display string.
  - Top-level tab screens use `<SunTop title right section />` (`src/components/sun/SunTop.tsx`); sub-screens use `<ScreenHeader>`.
  - Sizes from the mockup's inline CSS (`docs/new-design-handoff/screens/H<theme><id>.dc.html`): body 16–17, secondary 14–15, smallest 13. Nothing below 13 px. Sentence case; no mono uppercase labels.
  - List rows: `.sun-list-row` (min 52 px, hairline between rows). Pills: `.sun-pill` (48 px; `aria-pressed="true"` = ink fill). Progress: `<SunBar>`; rings: `<Ring>` (`src/components/sun/Ring.tsx`). One primary button per screen, at the bottom (`<Button>`), secondary = `<Button variant="secondary">`.
  - Colours: Tailwind token classes only (`bg-soft`, `bg-sage text-on-sage`, `bg-btn text-btn-ink`, `text-ink2`, `border-hairline`, `bg-track`, `text-accent-text` for accent-coloured text, `bg-accent` for marks) or `var(--ll-*)`. Never a hex value in a component (lint fails).
  - 44 px targets, real `<button>` / `<a>` / `<label>`, `aria-label` on icon buttons, visible focus.
- The mockups are pictures, not components, and most are first drafts (handoff §8.2): the style is fixed, the layout is a starting point, and **the PRD and the existing behaviour win**. Mockup numbers are sample data. Where a mockup drops a feature for calm, keep the feature in the nearest quiet spot (handoff §8.1). Use the app's own pictograms and muscle maps (`@/illustration/Pictogram`); wrap a pictogram's container in `className="sun-picto"` when it sits on a card.
- Copy: every new string goes in your area's copy file (reachable as `en.sun.<area>…`). Reuse existing `en.*` strings wherever they fit.
- Echo (FR-DSN-8): `ripple()`, `celebrate()` and `celebrateOnce()` from `@/app/echo` are no-ops in the classic look, so call them unconditionally at the event (food logged, weigh-in saved, workout finished, food goal reached). Rules in `src/engine/echo.ts`.

## Checking your work

- `npx tsc -b --noEmit` (other areas are being edited at the same time: fix errors in your files, ignore errors in files you do not own).
- `npx eslint <your files>` and `npx prettier --write <your files>`.
- `npx vitest run <your new test file> <the existing test files that cover your screens>`. Name tests after requirement IDs, e.g. `it('FR-DSN-10 (S12): …')`. Tests switch the look with `applyLook({ design: 'sun' })` in `beforeEach` and back to `'classic'` in `afterEach` (see `src/screens/m13-screens.test.tsx`).
- Look at it. Start your own dev server on your own port (`npx vite --port <port> --strictPort`, in the background) and shoot both themes: `MSYS_NO_PATHCONV=1 SHOOT_BASE=http://localhost:<port> SHOOT_LOOK=sun SHOOT_SCALE=1 SHOOT_SHEET=4 SHOOT_SETUP='/dev/fixture?auto=1&active=1' npx tsx scripts/shoot.ts <a folder in your scratch space> name=/route …`, then open the contact sheets and compare with the mockup PNGs. Check 360 px wide too where a layout is tight. Stop your server when done.
- Do not run `npm run build`, `npm run e2e`, `npm run test` (whole suite) or git commands: the lead integrates, runs the full suites and commits.
- Do not edit files outside your area. If a shared file needs a change, or you make a call where the handoff and PRD are silent or conflict, write it in `docs/plans/notes-<area>.md` (date, gap, decision, why); the lead moves these into `DECISIONS.md`.
