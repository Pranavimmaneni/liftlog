## M5 report

**Built**
- **XP, levels, streaks, milestones and the weekly quest (FR-XP-1…6).** All of it is derived from the log with the xp.json values, and nothing is stored as a running total, so editing a set changes XP.
  - **XP per session:** goal sets, bonus reps (capped per exercise), one extra set, PRs, session complete, week complete, the weekly quest and the first-session welcome, all within the 600 per-session cap. Calibration and "hurts" sets earn nothing.
  - **Levels:** thresholds from `250·n^1.35` (cumulative), with titles Rookie → Iron → Steel… The level shows on Home and on the ticket with its progress bar.
  - **Streak:** consecutive complete weeks. Every 8 weeks bank a rest-week pass, which covers the next missed week automatically. It shows as the "3-wk streak" chip on Home, as in the mockup.
  - **Milestones:** tonnage thresholds with a fun equivalent ("about 3.8 × Honda Civic"), session counts and your first bodyweight pull-up, each a one-time card on the ticket.
  - **Weekly quest:** generated from last week's weak spot (missed sessions → weakest muscle → beat 3 lifts), shown on Home with progress and completed automatically (+75 XP).
- **Ticket (FR-SUM-2).** Level card with "+N XP" and a progress bar, milestone cards, and **Share**, which draws the ticket as a 1080×1350 PNG in the current theme. It uses the share sheet where available and downloads the file otherwise.
- **PR stamp (FR-XP-3)** on the logger row of the set that beats your best estimated 1RM.
- **S22 QR (FR-PLT-5).**
  - `/scan` opens the camera with a viewfinder and uses BarcodeDetector where it exists. Otherwise (iOS) it uses the **self-hosted** zxing-wasm reader, loaded only on that screen and precached for offline use.
  - A sticker opens `/m/<machine>`: with a workout open it goes to that machine's logger (adding the exercise if needed), otherwise to the exercise page.
  - Unknown codes say "This sticker isn't from your LiftLog".
  - **Sticker sheet:** a printable 3-column grid of QR codes with machine name and pictogram, generated from My Gym (Settings → My gym → Print machine stickers).
- **FR-DATA-2 backup nudge** on Home, 7 days after the last backup and after every 10th session. "Back up now" / "Not now".
- **S21 install help (FR-PLT-8).** Three illustrated steps for iPhone Safari or Android Chrome, plus "Install now" where Chrome offers it. A note says the tab, the installed app and the APK keep separate data. A one-time banner in the browser tab links to it.
- **S26 states.** A storage-error banner ("couldn't save… Export backup") appears on IndexedDB failures. The empty states and delete confirmations from earlier milestones were re-checked in the accessibility sweep.
- **Accessibility (NFR-A11Y-1).** A new e2e test visits **every screen** (21 views) with demo data and runs axe (WCAG 2.2 AA) in Paper and Iron on both phones. It found and fixed:
  - headings placed directly inside the library `<ul>`;
  - a low-contrast link on the install page.
- **Performance (NFR-PERF).**
  - `npm run budget` (also in CI) checks the first-load JS, now **163 KB gzipped** (budget 250). The library data, pose data, charts and QR decoder stay lazy.
  - Lighthouse (mobile, Brotli like Vercel): **onboarding 90 / 100 / 100 / 91**, **install page 94–96 / 100 / 100 / 91** (performance / accessibility / best practices / SEO).
  - To get there: a static boot splash, resolving the first-visit onboarding redirect before the router starts (one lazy chunk instead of two), and keeping the backup/zod code out of the first load.
- **Lighthouse CI.** `.github/workflows/lighthouse.yml` plus `lighthouserc.cjs`, asserting every category ≥ 0.9. It audits the Brotli-served build on every push. When Vercel reports a preview it audits the preview too, which needs the bypass secret (TODO).
